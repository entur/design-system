## Typografi migreringsguide

Denne guiden hjelper deg med å migrere fra de gamle typografi-komponentene til det nye beta typografi-systemet.
Migreringsscriptet er laget basert på frontend-repoer vi forvalter, derfor vil ikke all migrering være 100%, det er derfor viktig å teste alle endringer selv også.

## Komplett migrering
- **Hva det gjør**: Oppdaterer både imports og komponentbruk til beta-komponenter
- **Konsekvenser**:
  - `<Heading1 className="ditt-klassenavn">` blir `<Heading className="ditt-klassenavn" as="h1" variant="title-1">`
  - `<Paragraph>` blir `<Text variant="paragraph">`
  - `<Link>` blir `<LinkBeta>`
  - Dine props og CSS-klasser blir med videre, derfor er det viktig å sjekke hva du overstyrer.
- **Når bruke denne**: Når du vil migrere til det nye systemet umiddelbart
- **⚠️ Viktig**: Test grundig etter migrering!

## Kom i gang

### Installer typografipakken (eller oppdater til siste verjson)

```bash
  npm install @entur/typography
```

```scss
// Importer styles
  @import '@entur/typography/dist/styles.css';
```

### Migrering

```bash
# Vis hjelp og alternativer
npx @entur/typography@latest migrate --help

# Se hva som ville blitt endret (trygt)
npx @entur/typography@latest migrate --dry-run

# Komplett migrering: oppdater alt til beta-komponenter
npx @entur/typography@latest migrate


```

`migrate` vil automatisk:
- Oppdatere alle imports
- Erstatte gamle komponenter med beta-komponenter
- Konvertere props til det nye formatet

```typescript
// Før migrering
import { Heading1, Paragraph } from '@entur/typography';

function MyComponent() {
  return (
    <div>
      <Heading1>Min tittel</Heading1>
      <Paragraph>Mitt innhold</Paragraph>
    </div>
  );
}
```

```typescript
// Etter komplett migrering
import { Heading, Text } from '@entur/typography';

function MyComponent() {
  return (
    <div>
      <Heading as="h1" variant="title-1">
        Min tittel
      </Heading>
      <Text variant="paragraph">Mitt innhold</Text>
    </div>
  );
}
```

## Sikkerhetsfunksjoner

Migreringsskriptet inkluderer flere sikkerhetsfunksjoner for å beskytte prosjektet ditt:

- **Tillatte mapper**: Skanner kun `src/**`, `app/**`, `components/**`, etc.
- **Blokkerte mapper**: Skanner aldri `node_modules`, `dist`, `.git`, etc.
- **Dry-run modus**: Test endringer uten å modifisere filer ved å bruke `--dry-run`
- **Tilpassbare stier**: Overstyr mapper med `TYPOGRAPHY_MIGRATION_DIRS` miljøvariabel
- **Standardmapper**: Skanner automatisk `src/**`, `app/**`, `apps/**`, `components/**`, `pages/**`, `lib/**`, `utils/**`, `styles/**`, `css/**`, `scss/**`
- **Filtypefiltrering**: Prosesserer kun TypeScript, JavaScript og SCSS/CSS filer

## Tilpassing av scriptet

### Default mapper som blir scannet

Migreringsskriptet skanner automatisk disse mappene:

- `src/**` - Kildekode
- `app/**` - Applikasjonsmapper
- `apps/**` - Flere applikasjoner
- `components/**` - Komponenter
- `pages/**` - Sider
- `lib/**` - Biblioteker
- `utils/**` - Hjelpefunksjoner
- `styles/**` - Stilfiler
- `css/**` - CSS-filer
- `scss/**` - SCSS-filer

Du kan overstyre standardmappene med miljøvariabelen `TYPOGRAPHY_MIGRATION_DIRS`:

#### Alternativ 1: Miljøvariabel

```bash
# Sett miljøvariabel
export TYPOGRAPHY_MIGRATION_DIRS="src/**,app/**,components/**"

# Kjør migrering
npx @entur/typography@latest migrate
```

#### Alternativ 2: Inline miljøvariabel

```bash
# Kjør med inline miljøvariabel
TYPOGRAPHY_MIGRATION_DIRS="src/**,app/**" npx @entur/typography@latest migrate
```

### Viktige sikkerhetsregler

- **Kun relative stier**: Ikke bruk absolutte stier som `/home/user/project`
- **Ingen parent-mapper**: Ikke bruk `../parent/directory`
- **Ingen home-mapper**: Ikke bruk `~/home/directory`
- **Glob-mønstre**: Bruk `**` for å skanne undermapper (f.eks. `src/**`)

### Eksempler på gyldige mapper

✅ **Gyldige:**
```bash
TYPOGRAPHY_MIGRATION_DIRS="src/**,app/**,components/**"
TYPOGRAPHY_MIGRATION_DIRS="packages/my-app/**,lib/**"
TYPOGRAPHY_MIGRATION_DIRS="frontend/**,backend/**"
```

❌ **Ugyldige:**
```bash
TYPOGRAPHY_MIGRATION_DIRS="/absolute/path"      # Absolutt sti
TYPOGRAPHY_MIGRATION_DIRS="../parent/directory" # Parent-mappe
TYPOGRAPHY_MIGRATION_DIRS="~/home/directory"    # Home-mappe
```

## Viktig: Ny margin-oppførsel

### Standard margin-oppførsel

Beta-komponenter har **ingen margin som standard** (`margin: 0`) på base-klassene, men **mange varianter legger til egne margins**:

**Før migrering:**
```jsx
<Heading1>Denne hadde automatisk margin</Heading1>
<Paragraph>Denne hadde også margin</Paragraph>
```

**Etter migrering:**
```jsx
// Med variant som har spacing
<Heading as="h1" variant="title-1">Denne har margin fra variant</Heading>
<Text variant="paragraph">Denne har margin fra variant</Text>

// Uten variant (kun base-klasse)
<Heading as="h1">Denne har ingen margin</Heading>
<Text>Denne har ingen margin</Text>
```

### Hvordan spacing fungerer

```jsx
// Variant med spacing (default med spacing)
<Heading as="h1" variant="title-1">Tittel med margin fra variant</Heading>
<Text variant="paragraph">Tekst med margin fra variant</Text>

// Eksplisitt spacing (overstyrer variant)
<Heading as="h1" variant="title-1" spacing="lg">Tittel med large spacing</Heading>
<Text variant="paragraph" spacing="md">Tekst med medium spacing</Text>

// Uten spacing (kun base-klasse)
<Heading as="h1">Tittel uten margin</Heading>
<Text>Tekst uten margin</Text>

// Fjern spacing fra variant
<Heading as="h1" variant="title-1" spacing="none">Tittel uten margin</Heading>
<Text variant="paragraph" spacing="none">Tekst uten margin</Text>
```

### Margin til spacing migrering

Migreringsskriptet oppdaterer automatisk `margin` props til `spacing`:

```jsx
// Før migrering
<Heading1 margin="bottom">Tittel</Heading1>
<Paragraph margin="none">Tekst</Paragraph>

// Etter migrering
<Heading as="h1" variant="title-1" spacing="md-bottom">Tittel</Heading>
<Text variant="paragraph" spacing="none">Tekst</Text>
```
